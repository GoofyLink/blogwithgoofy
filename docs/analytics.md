# 访问统计

后台入口：`/admin/dashboard`。两期功能统一使用新埋点数据，不合并文章旧浏览量，也不回填历史数据。后端启动自动创建统计表。

## 看板内容

- PV、UV、会话数、平均有效停留。
- 单日按小时、多日按日期展示趋势；支持今天、昨天、近 7 天、近 30 天和最近 365 天内的自定义区间。
- 模块按 UV、PV、平均停留排序，点击模块查看其热门内容；热门页面最多 100 条。
- 来源域名、搜索引擎、设备分布，以及 AI 工具、动漫观看链接和其他外链点击。

## 本地查看测试数据

开发环境默认不上报；登录管理员后，前台浏览也默认不上报。后台页面始终不计入。

1. 在仪表盘底部展开「统计口径与调试」。
2. 勾选「此浏览器启用本地开发埋点」，登录状态下同时勾选「此浏览器上报管理员测试访问」。
3. 打开前台页面，浏览不同模块并停留、点击链接。
4. 回到仪表盘，勾选「包含管理员测试访问」，点击刷新。

开关仅作用于当前浏览器。生产构建默认上报匿名前台访问，无需开启开发开关。

## 统计口径

- 页面主数据请求成功、渲染后产生一次 PV。刷新重新计次；同一路径的查询参数和锚点变化不重复计次。失败详情不计入。
- UV 按浏览器随机标识去重，不代表准确的自然人数。跨设备、清除存储会形成新访客；全站 UV 在整个筛选区间去重，不能把各天或各模块 UV 相加。
- 会话以 30 分钟无活动为界。有效停留仅累计可见页面且最近 60 秒有操作的时间，单页最多 4 小时；平均停留为有效秒数除以 PV。
- 使用北京时间。首次接收访问的服务器日期、小时决定归属；后续停留和点击归入该次访问的日期，不按跨午夜时长拆分。
- 来源采用页面入口 referrer 的域名；站内来源或缺失 referrer 归为直接访问。设备根据 User-Agent 估计。
- 点击只统计外部 HTTP(S) 链接，目标仅保存域名；站内跳转由页面访问记录体现。

## 数据与接口

`POST /api/v1/analytics/events` 接收页面、累计停留和点击事件，每批最多 10 条、32 KB。页面由服务器校验并确定模块和标题，草稿和后台路径不会写入。事件 ID 去重，停留按累计最大值增量更新，重试不会重复累加。客户端每 15 秒上报，关闭页面尝试 beacon；失败最多重试 5 次，内存队列最多 100 条。

`GET /api/v1/admin/analytics` 需要管理员认证，支持 `start`、`end`、`module`、`includeAdmin`。

- `analytics_visits`：访问身份和累计时长，保留 90 天。
- `analytics_receipts`：事件去重凭据，保留 90 天。
- `analytics_facts`：按日期、小时、页面、来源、设备、访客、会话、操作归并的统计事实，保留 365 天。包含散列浏览器标识用于区间精确去重，并非只有总数。
- `analytics_states`：统计启用时间。

浏览器标识和会话标识使用服务端 HMAC 散列保存，统计表不保存原始 IP、完整 referrer、查询参数或令牌。令牌只用于识别管理员测试访问。更换 JWT secret 会改变散列标识，影响跨变更时段的去重。

后台每 6 小时清理到期数据。每个来源 IP 每分钟最多 120 次上报请求，并过滤常见机器人标识；这不是完整的反作弊系统。拦截器、断网、关闭浏览器和停留在页面超过事件有效期可能造成漏报。看板数据在刷新时更新。

## 验证

前端：在 `web` 执行 `npm run build`。

后端：在 `server` 执行 `go test ./...`。设置 `ANALYTICS_TEST_CONFIG_DIR` 为含 `config.yaml` 的后端目录可启用 MySQL 集成测试；测试流量在事务中回滚，表结构和统计启用记录会保留。
